# 看视频时弹幕像低刷新率、晃鼠标才顺

!!! info "一句话"
    先分清是「解码不够」还是「帧调度/跨卡同步」问题，两者修法完全不同。

## 现象

B 站视频本身挺流畅，但弹幕层有残影/顿感；一晃鼠标就顺，不晃过一会儿又开始。

## 环境

niri + 外接 170 Hz + Chrome 原生 Wayland；最初 Chrome 跑在 4060 上软解。

## 排查

按顺序排除，别跳步：

```bash
niri msg outputs | grep -A3 H27T22S          # 1) VRR 是不是根本没开
cat /proc/$(pgrep -x niri)/cmdline >/dev/null # 2) 合成器在哪个 GPU（跨卡？）
chrome://gpu                                  # 3) Decoding: 是否为空（软解？）
```

本机实测的排除过程：VRR `supported, disabled`（排除了 VRR 抖动）→ Chrome 在 4060 上且
`Decoding:` 为空（确认软解）→ 换 780M 后 CPU 从 102% 降到 51%，但残影仍在
→ 指向跨卡同步（见《跨卡合成导致撕裂》）。

## 原因

两个原因叠加：① 4060 上 Chromium 不给 VA-API，全靠 CPU 软解；② 改用核显硬解后又变成
跨卡合成，没有显式同步，于是残影来自同步而不是算力。

## 解决办法

1. 先让硬解真的生效（`--render-node-override=<核显 render 节点>`，见 Chrome 那条）；
2. 再压跨卡撕裂（`wait-for-frame-completion-before-queueing`，只在跨卡的档位开）。

`--disable-frame-rate-limit` 只能当诊断用：解除 vsync 后 renderer 103%、gpu-process 130% CPU、
CPU Tctl 94 ℃、风扇 5900–6100 RPM，不能日常用。

## 怎么确认好了

弹幕残影消失，同时 CPU/温度在合理区间（本机 51% / 52–54 ℃），
而不是靠把显卡关掉换来的「低 CPU」。
