# 02 包管理

> 最后核对：2026-11-24。pacman 2011 个包（显式 334 / AUR 外装 87）。

## 现状

```
pacman -Q  | wc -l      → 2011   总包数
pacman -Qe | wc -l      →  334   显式安装（其余是依赖）
pacman -Qm | wc -l      →   87   AUR/外装（仓库里没有的）
du -sh /var/cache/pacman/pkg → 11 G（2993 个文件，等着 pacman -Sc）
```

## 日常

| 想干什么 | 命令 | 备注 |
|---|---|---|
| 更新系统 | `paru -Syu` | 别在 Steam 跑着时改 `localconfig.vdf` 那类文件 |
| 只查有没有更新 | `paru -Qu` | 升级前先看这一眼，尤其 nvidia/mesa/niri 三项 |
| 更新镜像源 | `mirror-update` | 自带脚本 |
| 检查所有待更新 | `checkallupdates` | 自带脚本 |
| 装东西 | `paru -S 包名` | **优先 AUR/仓库包，不要直接下 AppImage** |
| 查文件属于哪个包 | `pacman -Qo /路径` | |
| 看包装了哪些文件 | `pacman -Ql 包名` | |
| 搜索 | `pacman -Ss 关键词` / `paru -Ss` | |

**装软件优先走包管理器**。裸 AppImage 没有升级链路、不参与依赖解析、出问题也没人管；
非要用就丢 `~/Applications`，别混进 `~/.local/bin`。

## 降级（更新翻车时）

```bash
ls /var/cache/pacman/pkg/ | grep 包名        # 本机缓存里有历史版本，最省事
sudo pacman -U /var/cache/pacman/pkg/包名-旧版本.pkg.tar.zst
```

缓存里没有就走 **Arch Linux Archive**：

```bash
# /etc/pacman.d/mirrorlist 临时换成
Server=https://archive.archlinux.org/repos/2026/11/20/$repo/os/$arch
sudo pacman -Syyuu        # 双 u 表示允许降级
```

自带脚本 `pacd` 是降级辅助。

**内核不降这件事是有结论的**：本机 7.3.5-zen 性能优秀，遇到问题优先绕过 / 上报，
不要靠降内核解决。（7.3.6 含官方修复，属于「升」不是「降」。）

## 清理

```bash
sudo pacman -Sc            # 清掉不在仓库里的旧包，11 G 会回收一大半（需你自己跑）
sudo paccache -rk2         # 只留最近 2 个版本（装 pacman-contrib 后可用）
paru -Sc                   # AUR 构建缓存
```

**删东西前先确认**：`/var/cache/pacman/pkg` 是降级的唯一退路，删空之后翻车就只能靠 ALA。

## 升级后的必查项

```bash
pacman -Qii 包名 | grep -i pacnew       # 有没有 .pacnew / .pacsave 等着合并
paru -Qu                                # 剩下的更新
grep -E 'upgraded' /var/log/pacman.log | tail -30   # 这次到底动了什么
```

**一次升级动了多个图形栈组件时，别把锅单独扣给显卡驱动。** 本机踩过：一次 `paru -Syu`
同时换了驱动、mesa、合成器、内核四个，之后的花屏不能归因成「驱动退化」。
