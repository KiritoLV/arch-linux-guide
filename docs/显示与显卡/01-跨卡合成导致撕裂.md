# Chrome 跑核显、niri 跑独显 → 跨卡合成导致撕裂/残影

!!! info "一句话"
    外接屏物理接在独显上，客户端却在核显渲染，跨卡 dmabuf 没有显式同步。

## 现象

看视频/弹幕时画面有撕裂或残影感；日志里 Chrome 报 `Drm prime capability is not supported`。

## 环境

外接屏接 RTX 4060（DP-9）；Chrome 用 `--render-node-override=/dev/dri/renderD128` 跑在 780M 上硬解；
niri 用 4060 合成扫描输出。niri 当前**没有** `linux-drm-syncobj-v1`。

## 排查

```bash
# 1) 确认是跨卡：谁在渲染 vs 谁在输出
grep -oE 'renderD[0-9]+' /proc/$(pgrep -x niri)/maps 2>/dev/null | sort -u
niri msg outputs | grep -A2 DP-9
# 2) 确认没有 explicit sync 协议
#    Chrome 日志：WARNING:ui/ozone/platform/wayland/host/wayland_drm.cc:114
#                 Drm prime capability is not supported
```

## 原因

跨 GPU 时缓冲要在两张卡之间传，只有隐式同步；niri 还没实现 `linux-drm-syncobj-v1`
（上游 issue #843 自 2024-12 一直开着，PR #3956 停在 0 review），所以撕裂是结构性的。

## 解决办法

短期只能 workaround：

```kdl
debug {
  wait-for-frame-completion-before-queueing
}
```

热重载即可生效（`niri msg action load-config-file`），不用重登。

**代价实测（PBZ，170 Hz，各 200/383 秒）**：开 → 72.3 fps / p99 20.44 ms；关 → 69.3 fps / p99 21.65 ms。
差 3 帧、1.2 ms 属场景噪声（关闭那局 GPU 占用 92% vs 90%），**测不出代价**。
社区 30 个相关 issue 全是「加了修好」；唯一负面是 #3774 在 300 Hz（3.33 ms 预算）报告顿挫。

本机落地：只在 **game 档**（跨卡）开，normal 档（niri 也走核显，同卡）不加。

## 怎么确认好了

看视频时撕裂/残影消失；游戏帧率与 p99 无退化（用 MangoHud 记录对比，注意两份必须是同一场景）。
