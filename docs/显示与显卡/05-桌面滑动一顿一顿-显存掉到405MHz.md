# 桌面滑动一顿一顿，过几秒就卡一下（显存掉到 405 MHz）

!!! info "一句话"
    高刷桌面偶尔整段掉帧，几秒一次；不是每个窗口都卡，是整块屏幕顿一下。

## 现象

滑动工作区时先卡一下、然后很顺、几秒后又卡一下。看日志有窗口单帧花屏的记录，帧率本身不低。

## 环境

niri 26.04 / RTX 4060 Laptop（外接 2560×1440@170）/ 620.73.04；完全不给 NVIDIA 频率下限。

## 排查

先看频率是不是在空载档，而不是先怀疑合成器：

```bash
timeout 16 nvidia-smi --query-gpu=clocks.current.graphics,clocks.current.memory,utilization.gpu,pstate \
  -lms 100 --format=csv
```

判据：**GPU 占用已经 90%，但核心/显存还停在低档**（例如显存 405 MHz）→ 就是 DVFS 升频太慢。
只看核心频率会误判：P0 和 P4 下核心都可能是 2250 MHz，差的是**显存档**，所以 P-state 才是判据。

## 原因

GPU 空闲后会掉到 P8 / 300 MHz / 显存 405 MHz。高刷桌面每秒合成 170 帧，
从深睡档爬回来要几十毫秒，中间这几帧就是看到的那一顿。

## 解决办法

给显卡一个频率地板，挡掉 P8 深睡档：

```bash
sudo nvidia-smi -pm 1
sudo nvidia-smi -lgc 840,3105        # 地板 840 MHz；上界是 VBIOS 理论上限
```

本机实测：地板 840 → 稳定 P5 / 840 MHz / 显存 810 MHz / 约 10 W。**不需要额外钉显存**（`-lmc`）。
高刷场景仍然偶发的话可以抬到 1000。

锁频是易失的，重启就没了 —— 开机自动重下（本机用 `niri-gpu-profile resume` 挂在 `spawn-at-startup`）。

## 怎么确认好了

```bash
nvidia-smi --query-gpu=clocks.sm,clocks.current.memory,pstate,power.draw --format=csv,noheader
# 期望：P5 档，核心不低于 840，显存不再是 405
```
