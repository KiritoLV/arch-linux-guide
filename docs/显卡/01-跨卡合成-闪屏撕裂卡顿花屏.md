# 第一类：跨卡合成 —— 闪屏 / 撕裂 / 残影 / 单帧花屏

!!! info "一句话"
    niri 在一块卡上扫描输出、客户端在另一块卡上渲染，中间没有显式同步，问题全从这来。

## 现象

外接屏物理接在独显上（本机 DP-9 接 4060），但客户端跑在核显上（例如 Chrome 指定了 780M 硬解），
于是出现其中任意一种：

- 闪屏 / 撕裂纹（画面上下错位一条）
- 弹幕、滚动内容有**残影感**，晃一下鼠标反而顺
- 高刷下任意窗口偶发**单帧花屏**
- VRR 明明配了却不生效，画面节奏仍然死锁在固定刷新率

共同点：**不是算力不够**，GPU 占用往往没满，但画面就是不安分。

## 环境

niri + 混合显卡（RTX 4060 扫描输出 / Radeon 780M 渲染）；niri 当前没有 `linux-drm-syncobj-v1`。

## 排查

先确认「两台机器」：谁渲染、谁输出。

```bash
# 1) 哪块卡在扫描输出（connector 挂在谁下面）
for c in /sys/class/drm/card[0-9]/device/vendor; do echo "$c: $(cat $c)"; done   # 0x10de=NVIDIA 0x1002=AMD
niri msg outputs | grep -E "Output|Current mode"

# 2) niri 自己用哪个 render 节点（game 档是 renderD129=4060）
grep -oE 'renderD[0-9]+' /proc/$(pgrep -x niri)/maps 2>/dev/null | sort -u

# 3) 客户端是不是走了另一块卡 —— Chrome 的例子
#    chrome://gpu → GPU1 *ACTIVE* 0x1002 就是跨卡
```

Chrome 的日志会直接点明：

```
WARNING:ui/ozone/platform/wayland/host/wayland_drm.cc:114 : Drm prime capability is not supported
```

同类里的 **VRR 不生效**也在这里查（它决定画面节奏是否被固定刷新率锁死）：

```bash
niri msg --json outputs | python3 -c "import json,sys;[print(n,o['vrr_enabled']) for n,o in json.load(sys.stdin).items()]"
niri msg --json windows | python3 -c "import json,sys;[print(w['app_id']) for w in json.load(sys.stdin)]"
# 注意：Proton/XWayland 游戏的 app_id 是 *.exe（本机实测 pbz.exe），不是 steam_app_*
```

## 原因

跨 GPU 时，渲染完的缓冲要经内存/P2P 传给扫描输出的那张卡，只有**隐式同步**：

- 渲染卡以为「这帧已经好了」，扫描卡的 DRM 却可能读到还没写完的缓冲 → 撕裂、单帧花屏、残影；
- 没有 `linux-drm-syncobj-v1` 就无法把 fence 显式传过去，所以这是**结构性**问题，
  不是调参能消掉的（niri issue #843 自 2024-12 一直开着，PR #3956 停在 0 review）。

VRR 那一条属于同一类的另一种表现：输出节拍固定（本机 170 Hz），而实际帧时间远大于一个刷新间隔，
渲染和提交的相位对不上，看着就是「顿」或「残影」。

## 解决办法

```kdl
debug {
  wait-for-frame-completion-before-queueing
}
```

它让 niri 每帧**等渲染完成再交给 DRM**，把隐式同步的窗口抹平（官方定位是诊断/绕障选项，
但社区 30 个相关 issue 全是「加了就修好」）。

**支持热重载，不用退游戏**：

```bash
niri validate -c ~/.config/niri/config.kdl && niri msg action load-config-file
journalctl --user -b | grep "niri_config: loaded" | tail -3
```

**只在跨卡的档位开**：本机 `game` 档（niri 用 4060、Chrome 用 780M）加；
`normal` 档 niri 也走核显，同卡无跨卡合成，加了纯多余。

顺带把 VRR 规则修对（不然画面节奏死锁在固定刷新率）：

```kdl
window-rule {
    match app-id=r#"^.*\.exe$"#
    variable-refresh-rate true
}
```

（`variable-refresh-rate true` = `VrrRule::On`，窗口可见即启用，**不要求全屏**。）

## 怎么确认好了

撕裂/残影/单帧花屏消失；`vrr_enabled` 在游戏窗口可见时为 True。

代价实测（PBZ，170 Hz，各 200/383 秒）：开 → 72.3 fps / p99 20.44 ms；关 → 69.3 fps / p99 21.65 ms。
差 3 帧、1.2 ms 属场景噪声（关闭那局 GPU 占用 92% vs 90%），**测不出代价**。
唯一负面报告是 niri #3774 在 300 Hz（3.33 ms 帧预算）上顿挫。
