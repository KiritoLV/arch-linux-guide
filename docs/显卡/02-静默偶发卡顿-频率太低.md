# 第二类：静默偶发卡顿 —— 频率太低（锁频解决）

!!! info "一句话"
    画面几秒顿一下、滑动先卡后顺，GPU 占用却是高的：卡在升频，不是卡在算力。

## 现象

没有报错、没有花屏，就是**安静地**每隔几秒卡一下：

- 滑动工作区：先卡一下 → 很顺 → 几秒后又卡一下
- 看视频/带动画界面偶发整段掉帧
- `mangohud` 之类显示占用很高，看起来「显卡在干活」

## 环境

niri + NVIDIA 独显扫描输出 + 高刷新率（本机 170 Hz）；完全没有给频率下限。

## 排查

**判据看 P-state 和显存频率，不看核心频率**：

```bash
timeout 16 nvidia-smi --query-gpu=clocks.current.graphics,clocks.current.memory,utilization.gpu,pstate \
  -lms 100 --format=csv
```

命中特征：**占用已经 90%，核心/显存却还在低档**（例如显存 405 MHz、P8）。

只看核心频率会误判：P0 和 P4 下核心都可能是 2250 MHz，真正差的是**显存档**，所以 P-state 才是判据。

## 原因

GPU 空闲后会掉进深睡档（P8 / 300 MHz / 显存 405 MHz）。高刷桌面每秒要合成 170 帧，
从深睡爬回来要几十毫秒——这几十毫秒就是看到的那一顿，而它只发生在「刚要用 GPU」的瞬间，
所以表现为偶发、静默、无日志。

## 解决办法

给一个频率地板，把深睡档挡掉：

```bash
sudo nvidia-smi -pm 1
sudo nvidia-smi -lgc 840,3105        # 地板 840；上界是 VBIOS 理论上限
```

本机实测：地板 840 → 稳定 P5 / 840 MHz / 显存 810 MHz / 约 10 W。
**不需要额外钉显存**（`-lmc`）。高刷仍然偶发的话把地板抬到 1000。

锁频是**易失**的，重启失效 —— 用开机脚本按档位重下（本机 `niri-gpu-profile resume` 挂在
`spawn-at-startup`，`normal` 档什么都不做）。

## 怎么确认好了

```bash
nvidia-smi --query-gpu=clocks.sm,clocks.current.memory,pstate,power.draw --format=csv,noheader
# 期望：P5，核心 ≥840，显存不再是 405
```
