    第三类：游戏黑屏但有声音 —— 跨卡首帧导入失败¶

    一句话

    niri 用核显合成、游戏在 NVIDIA 上渲染时，进游戏整屏黑但声音正常；让独显先在 wayland 上呈现一次（跑一下 vkcube）就恢复，而且恢复之后不会再犯。

    现象¶

    • 启动游戏（本机：幻兽帕鲁式的 Proton 游戏、pbz.exe）→ 屏幕全黑，但游戏音乐/音效一直在响，键鼠也有反应（能切窗口、能退出）
    • 反复启动游戏，偶尔一次就出画面 —— 只要成功一次，后面就不黑了，直到下次重登/重启
    • 前台切到别的窗口正常，说明不是整台机器没输出，只是游戏那张画面没到屏幕上

    环境¶

    • Arch Linux，niri 26.04（niri-gpu-profile normal 档：ignore-drm-device 忽略 4060，niri 用 Radeon 780M 合成）
    • 外接屏接在核显侧接口（DP-2，amdgpu），游戏仍用 DRI_PRIME=1 跑在 RTX 4060 上
    • 音频走 PipeWire（与显示路径无关，所以永远正常）

    排查¶

    # 1) 谁在合成（normal 档应该是核显 = renderD128）
journalctl --user -b | grep "using as the render node" | tail -1

# 2) 有没有走跨卡 / 退回 CPU 拷贝
journalctl --user -b | grep -iE "multigpu|cpu-copy|Failed to import" | tail

# 3) 游戏是不是真在独显上（排除「游戏根本没起来」）
nvidia-smi pmon -c 1

# 4) 有没有 GPU hang / Xid
dmesg | grep -iE "nvidia|amdgpu" | grep -iE "xid|hang|reset" | tail

    关键判据：能听到声音 + 2) 里出现 Falling back to cpu-copy 或 Failed to import buffer + 4) 干净，那就是本条，不是显卡挂了。

    原因¶

    客户端在 4060 上渲染出来的 dma-buf，要交给 780M 合成、再由 780M 送屏，这是跨卡合成：

    • NVIDIA 的 EGL 只肯输出 block-linear modifier，AMD 侧无法直接 import，smithay 会退回 CPU 拷贝（niri #4374 的用户日志实测：Error importing dmabuf from renderD129 to renderD128 → Falling back to cpu-copy）
    • 这条跨卡路径第一次建立时可能导入失败 / 产出无效帧，于是游戏那一层的画面被丢弃，而音频走的是 PipeWire 的另一条路，完全不受影响 → 黑屏有声
    • 「成功一次后就一直正常」：成功那一次把跨卡 buffer 与 import 状态建立并缓存下来，之后沿用同一条已就绪的路径 —— 这是对本机现象的机理解释，未在源码层面证实；能确定的是现象稳定可重复（本机多次实测）

    解决办法¶

    ① 当场救急（进游戏前跑一次）

    DRI_PRIME=1 vkcube --c 5      # 5 帧即可，本机实测 0.3 s，退出码 0

    它让 4060 通过 wayland 真正呈现一次（Selected GPU 0: NVIDIA GeForce RTX 4060 Laptop GPU, type: DiscreteGpu），把跨卡那条路「走通并记住」，之后进游戏就出画面。

    ② 自动化：放进登录自启，normal 档每次进 niri 自己跑

    // ~/.config/niri/config.kdl
spawn-at-startup "/home/kirito/.local/bin/niri-gpu-profile" "resume"

    resume 里按档位分工：game → 重下 -lgc 锁频；normal → 跑一次 DRI_PRIME=1 vkcube。 手动触发：niri-gpu-profile refresh（不用重登）；日志在 ~/.local/state/niri-gpu-profile/refresh.log。

    ③ 根治：别跨卡

    • 让 niri 整体用独显合成：debug { render-drm-device "/dev/dri/renderD129" }（代价：续航明显变差）
    • 或者 UEFI 里有 MUX 就切到独显直连
    • 上游的 per-output 合成（每块卡管自己那块屏）还没有：niri #3969 至今 open、无维护者答复

    怎么确认¶

    # 跑完 vkcube 后应该看到 vkcube 短暂出现在独显上
nvidia-smi --query-gpu=utilization.gpu --format=csv,noheader

# 然后启动游戏：有画面 = 生效；再把 vkcube 跑一次不会让黑屏回来
