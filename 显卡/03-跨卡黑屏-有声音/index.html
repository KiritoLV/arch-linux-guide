    第三类：游戏黑屏但有声音 —— 跨卡呈现路径没建立¶

    一句话

    混合显卡 PRIME（屏幕挂在核显上、游戏在 NVIDIA 上渲染）时，开机后第一个在独显上成功的 Vulkan 呈现如果来自 Steam/Proton 内部，就会坏掉：游戏黑屏但有声音。先跑一次 vkcube 让它在 Proton 之外呈现一次，之后整个会话正常，直到重启。

    现象¶

    • 从 Steam 启动 Proton 游戏 → 窗口在、屏幕全黑，但音乐音效一直在响，键鼠有反应（能切窗口、能退出）
    • nvidia-smi 显示游戏确实在独显上跑：占用高、显存吃 1–2 GB —— 不是游戏没起来，是画面没上屏
    • 反复启动游戏，偶尔一次就出画面；成功一次之后一直到重启都不再犯
    • 同一个程序从 Steam 之外跑（prime-run vkcube、非 Steam 快捷方式）画面正常 —— 只有 Proton 那条路坏

    环境¶

    • Arch Linux，niri 26.04（本机 niri-gpu-profile normal 档：ignore-drm-device 忽略 4060，niri 用 Radeon 780M 合成）
    • 外接屏接在核显侧接口（amdgpu），游戏用 DRI_PRIME=1 跑在 RTX 4060 上
    • 音频走 PipeWire，与显示路径无关 —— 所以永远正常
    • 上游更普遍的形态：Intel 核显 + NVIDIA 独显、Hyprland/XWayland、Steam 64 位 steamrt64 客户端

    排查¶

    # 1) 先抓一次「失败的那次」的 Proton 日志，再动别的
PROTON_LOG=1 PROTON_LOG_DIR=/tmp %command%
L=$(ls -t /tmp/steam-*.log | head -1)

# 2) 换链失败的签名
grep -ac "Failed to create swapchain, vr -13" "$L"      # >0 = 命中本条
grep -aE "Creating swapchain|Ensure maximum latency" "$L" | head -3
#    健康的一局：-13 计数为 0，且只有一条 Creating swapchain

# 3) 游戏是不是真在独显上（排除「根本没起来」）
nvidia-smi pmon -c 1

# 4) 有没有 GPU hang / Xid
dmesg | grep -iE "nvidia|amdgpu" | grep -iE "xid|hang|reset" | tail

# 5) 其他成因（本机长期 PROTON_ENABLE_WAYLAND=1，这两条基本可跳过，留个判据）
grep -nE "Could not find output|wayland_output_array_zero|output_info_array_select" "$L"

    判据：有声音 + 游戏在独显上跑 + 4) 干净 → 本条。若 5) 命中，那是另一条路（去掉 PROTON_ENABLE_WAYLAND），别一次改两样。

    原因¶

    vr -13 就是 VK_ERROR_UNKNOWN，来自 vkCreateSwapchainKHR。整条链：

    1. 开机后，独显一侧的呈现（present）路径还没被任何进程用过；
    2. Proton 游戏在 pressure-vessel 容器 + steamrt64 运行时里，于「PRIME 跨卡、屏幕由核显驱动」的拓扑上创建 swapchain，这条协商对不上 → 返回 VK_ERROR_UNKNOWN；
    3. vkd3d-proton 每次 present 都重试 recreate，所以启动时失败一次就 latch 整个进程：几千次重试、永不恢复、窗口恒定黑 —— 画面没了，声音（另一条路）照常 → 黑屏有声；
    4. 重开游戏等于把这次"只做一次"的协商重掷一遍，所以偶尔能中；中过的那次是一次成功的呈现，从此驱动侧状态就是好的，一路好到重启。

    证据等级（别混着讲）

    • 实测：本机反复出现，vkcube 一次即治好（多例）；上游 #13876 里多人给出同一现象与同一做法
    • 上游结论：Steam 64 位 steamrt64 运行时（build 1794424036，2026-11-12）之后，"开机后第一个在 NVIDIA 上渲染的东西必须来自 Proton/pressure-vessel 之外，之后 Steam 里的游戏就正常"（#13876 评论原话）；同帖还有 Battle.net 同症、同样被这招治好
    • 未证实（不要当结论讲）：跨卡 dmabuf 的 modifier/格式协商具体卡在哪一环；也观察到过日志里 -13 计数为 0 的黑屏被同一招治好 —— 最终落点是"驱动/呈现状态"，不止一个错误码
    • 排除项（实测）：本机 Proton 游戏长期带 PROTON_ENABLE_WAYLAND=1，所以「XWayland 换链失败」那条成因不成立 —— 不是推测，是配置一直在那儿
    • 别往这边找：跨卡合成导致的 CPU 拷贝（Falling back to cpu-copy）是性能问题，跟这条黑屏不是一回事。同一台机器上两件事都会发生，最容易被串成因果（这条第一版就串错过）

    解决办法¶

    ① 当场救急 / 开机跑一次（这是目前唯一的现成根治手段）

    prime-run vkcube --c 5                   # 本机实测：5 帧、0.3 s、exit 0
prime-run vkcube --wsi xcb --c 60        # 上游那台用这条；哪个 WSI 都只是「让它呈现一次」

    它成功呈现一次，状态就好了。已经黑着的时候跑也有效，稳妥做法是跑完再启动游戏。

    ② 自动化：登录时跑一次

    // ~/.config/niri/config.kdl —— 本机已按档位固化在脚本里
spawn-at-startup "/home/kirito/.local/bin/niri-gpu-profile" "resume"

    resume 在 normal 档自动跑 DRI_PRIME=1 vkcube（game 档不跑，它本来就在独显上合成）。 手动触发：niri-gpu-profile refresh；日志 ~/.local/state/niri-gpu-profile/refresh.log。 Hyprland 的等价写法：exec-once = prime-run vkcube --wsi xcb --c 60。

    ③ 不想每次跑：别跨卡

    • 让合成器整体用独显合成（debug { render-drm-device ... }）或切 MUX 直连 —— 代价是续航
    • 或者 gamescope 把游戏包一层独立合成器（多一次合成，几 % 成本）—— 是绕开，不是修复

    怎么确认¶

    # 跑完 vkcube 后启动游戏：有画面 = 生效
# 想量化就看这一局日志的计数
grep -ac "Failed to create swapchain, vr -13" ~/steam-<appid>.log   # 期望 0
grep -ac "Creating swapchain" ~/steam-<appid>.log                   # 期望 1

    判据是「这一局的日志」，不是「这次能开」—— 重开本身就有概率中，光看能不能开不算证据。

    参考¶

    • 已排除、别往这边找：XWayland 路径上缺 PROTON_ENABLE_WAYLAND=1 造成的同类 vr -13 —— 本机所有 Proton 游戏一直挂着 PROTON_ENABLE_WAYLAND=1，这条路不适用
    • niri FAQ：外接屏接独显 / 内屏接核显时的跨卡合成与卡顿
    • 本项目实测无效、别再试的：BufferCount 2/4、ReShade/DLSS 注入、VKD3D_DISABLE_EXTENSIONS、VKD3D_SWAPCHAIN_LATENCY_FRAMES=1、换 vkd3d-proton 版本
