    Chrome 在 NVIDIA 上根本不做硬解¶

    chrome://gpu 里那行 Video Decode: Hardware accelerated 看着挺正常，但往下 Video Acceleration Information → Decoding: 一条都不列；播视频时 CPU 高、风扇转，nvidia-smi 里 NVDEC 占用是 0%。

    问题描述¶

    Chromium 的 VA-API 实现里写死了跳过 NVIDIA 设备，它自己的日志就直说：

    WARNING:media/gpu/vaapi/vaapi_wrapper.cc:131 : Should skip nVidia device named: nvidia-drm

    所以不是"没配好"，是不支持。在 NVIDIA 上怎么加 flag，<video> 最后都会回退到软解；那行 Hardware accelerated 是假象，判断硬解有没有生效只认 Decoding: 列表。

    Firefox 不一样，它的 VA-API / NVDEC 是支持 NVIDIA 的。

    解决办法¶

    按机器形态选一条：

    只有 NVIDIA（独显直连） → 视频用 Firefox。什么都不用绕，也没有跨卡问题。

    有核显（本机这种） → 让 Chrome 跑在核显上做硬解：

    # ~/.config/chrome-flags.conf
--render-node-override=/dev/dri/renderD128

    节点编号用 lspci 或 /dev/dri/by-path/ 确认一下再写死。这样 h264 / vp9 / hevc / av1 都能硬解，代价是引入了跨卡合成（Chrome 在核显渲染、合成器在独显输出），画面要是开始撕、拖影，就按「画面闪、撕、拖影」那篇处理。

    一个常见的坑：--use-gl=egl 在 Chrome 158 是非法值，会让 GPU 初始化失败、整个浏览器退化成软件渲染（日志里 gl_factory.cc:110 … not found in allowed implementations）。

    配好之后 chrome://gpu 里应该能看到：

    GL_RENDERER: ANGLE (AMD, AMD Radeon 780M Graphics (radeonsi phoenix ACO), …)
Decoding: h264 baseline/main/high、vp9 profile0/2、hevc main/main10、av1 main

    顺带一句：别拿"CPU 占用变低"当优化生效的证据，GPU 被整关掉时 CPU 反而可能更低，先确认 GL_RENDERER 里真是那块显卡。
